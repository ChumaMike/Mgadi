VOICE COMPANION (branch feature/live-voice-companion; OFF unless configured; nothing here has been deployed or tested against a real Retell account)
Full details and the provider checklist are in VOICE-COMPANION.md. For a Vercel project:
1. Install/build: vercel.json runs `npm run build`, which runs the engine bundle (public/vendor/retell-client.js from the pinned retell-client-js-sdk), makes the icons and writes the offline manifest. Vercel runs the install first. If the engine bundle is missing the app still works and voice is reported unavailable. The offline manifest is different by host: the local server (server.js) builds it from the served files at request time, but on Vercel the files are served statically, so /precache-manifest.json exists only if the build step ran. If it is missing there the app reports that the offline copy could not be saved (it does not pretend).
2. Environment variables (Vercel project settings, never in Git): MGADI_VOICE_MODE=retell, RETELL_API_KEY (private), RETELL_PUBLIC_KEY, RETELL_AGENT_ID_EN, and MGADI_VOICE_VERIFIED_LANGUAGES only after speaker tests. Leave MGADI_VOICE_MODE unset to keep voice off.
3. The Retell public key must allow the deployed domain. Preview deployment URLs change each time, so a preview needs its domain added too.
4. Security headers changed by: Permissions-Policy microphone=(self); CSP connect-src adds https://api.retellai.com and wss://api.retellai.com; Cross-Origin-Resource-Policy same-origin was added later. Cross-Origin-Opener-Policy is deliberately NOT set (see SECURITY-REVIEW.md). The local server and vercel.json are tested to carry identical values.
5. Voice limits use a shared store when UPSTASH_REDIS_REST_URL/_TOKEN (or KV_REST_API_URL/_TOKEN) are set. Without one, PUBLIC voice is refused on Vercel (fail closed); only operator tests work. Provisioning a store may cost money: ask first. Also set a Retell spend limit.
6. Smoke checks after a preview exists: on a real phone over HTTPS with synthetic speech only: consent, mic prompt, connect, live captions, mute, end, bank button during a call, reconnect after toggling flight mode, and confirm in the Retell dashboard that no transcript or recording was stored.


EMERGENCY AND OFFLINE READINESS (branch feature/emergency-offline-readiness; NOTHING HAS BEEN DEPLOYED; every step below needs the owner's go-ahead)
Evidence and decisions: RELEASE-READINESS.md. Risks: SECURITY-REVIEW.md. First real call: VOICE-REAL-TEST.md.

What changes for a deployment
- Offline: the app now registers a service worker (/sw.js?v=<version>) and serves /precache-manifest.json (built from the served files). Both are covered by vercel.json headers (sw.js no-cache with Service-Worker-Allowed /; the manifest no-store). Offline needs HTTPS (a Vercel URL is HTTPS) and one completed online visit.
- The build must run: `npm run build` (vercel.json buildCommand). Build output is git-ignored by design.
- Operator test: allowed on a Preview deployment (VERCEL_ENV=preview); REFUSED on Production unless MGADI_OPERATOR_ALLOW_PRODUCTION=yes. The token is honoured only over https (Vercel sets x-forwarded-proto) or from the same machine. If that header were ever missing the token is ignored (fails closed).
- Public voice stays off unless MGADI_VOICE_MODE=retell, a verified language is listed in MGADI_VOICE_VERIFIED_LANGUAGES (only after the real test), AND a shared quota store is configured.
- Hosted triage remains rules-only (api/triage.js has no AI adapter), so no paid call sits behind it.
